# E6 — Frontend público do Observatório Popular

## Resumo para quem vai usar

A interface do Figma Make foi implementada em React, com sua identidade
vermelha, fotografia, fontes, ícones, painéis e versões para computador e celular.
As onze telas têm rotas próprias. A prioridade final definida pelo responsável
é mostrar os dados corretos de Lula em 2026, primeiro turno, com 2022 disponível
como comparação. Não há resultados de outros candidatos na interface pública.
Comparecimento e abstenção descrevem o eleitorado inteiro do recorte.

Os arquivos de 2026 estavam nos ZIPs locais. Foram extraídos sem modificar seu
conteúdo e incorporados pelo pipeline de ingestão. A leitura integral do CSV de
votos de 2026 encontrou **53.879.538 votos para Lula**. O detalhe nacional registra
**119.306.034 votos válidos**, correspondente a **45,1607820606961%** para Lula.
O headline do Figma de **45,16%** coincide com essa fonte. Seus **57.259.504 votos**
pertencem a Lula em 2022, primeiro turno. A projeção de 62,8 milhões/48,20% no
protótipo não é um resultado observado de 2026 nesses arquivos.

O site oferece consultas, filtros até a seção, comparação, participação e
downloads locais. Mensagens gerais de mobilização são preservadas. Pontuações
de conversão, prioridades de persuasão por seção e mensagens políticas por
perfil não são implementadas. Geometrias, Censo e endereços de locais de votação
ausentes produzem estados explícitos de indisponibilidade.

A entrega é local; não foi publicada na internet. Os links de ferramentas,
contato, GitHub e doação dependem de configuração pelo responsável. Não há
cadastro ou pagamento simulado.

## Implementação de engenharia

`frontend/`: React 19, TypeScript, Vite 8.3.4, Tailwind 4, React Router,
TanStack Query e ECharts. Páginas carregam sob demanda. Fonts Inter/IBM Plex Mono
e fotografia são locais, com manifesto de origem e SHA-256. Os dezesseis SVGs
vieram do código exportado. Tokens centralizam paleta, fontes, container, header,
espaçamento e sombras; breakpoints originais de 760/1100 px foram preservados.

Filtros variáveis são ano, turno, UF, município TSE, zona e seção. Presidente e
Lula ficam fixos, inclusive quando parâmetros da URL tentam substituí-los.
Alterar um nível ascendente limpa seus descendentes. Código territorial permanece
texto literal; não se formata município ou seção como uma quantidade numérica.
Os filtros aplicados acompanham a URL e os downloads.

Quantidades chegam como strings decimais e são formatadas com `BigInt`, sem
perda de precisão JavaScript. Gráficos recusam valores fora do intervalo exato
de JavaScript ou ausentes, conservando a tabela como leitura exata. Taxas e
diferenças eleitorais vêm do backend; nenhum denominador é estimado no frontend.
`NULL` permanece “Indisponível”, nunca zero. Cache e consultas de detalhe/lista
usam `data_version`; mudança de versão invalida a fonte antes de misturar dados.

`src/eleitoral/api/`: API FastAPI, `/api/v1`, somente leitura de sete Parquets
públicos autorizados. Endpoints: health, metadata, elections, candidates,
geographies, results, sections, comparisons, turnout, invalid-votes, maps e census.
O consumidor público não abre o banco DuckDB de trabalho e não fornece escrita,
ingestão ou SQL arbitrário. Parâmetros são validados e vinculados ao SQL; limites
de paginação, concorrência, memória, tempo e rate limit são explícitos. CORS usa
origens configuradas. Erros são sanitizados. Startup confere hashes, schema,
contagens, tipos, versão e exclusão de demonstrações.

A documentação de [publicação](../deploy/publicacao.md) descreve serviço/API,
volume somente leitura, domínio, HTTPS, proxy `/api` e fallback SPA. A
[atualização](../deploy/atualizacao-dados.md) usa CLI oficial e novas versões
imutáveis, com rollback; nunca modifica os Parquets servidos.

## Preparação das fontes e tratamento causal

| Fonte extraída do ZIP | SHA-256 |
| --- | --- |
| `votacao_secao_2026_BR.csv` | `7bb56772992f6a448494331e6a1191a2f3cbd4dd1ed25efe4e84c998af265a3c` |
| `detalhe_votacao_secao_2022_BR.csv` | `611843dc968ac4a5c0b72f97b8799f88c678fd9f654829ad0c524477f7c24b5e` |
| `detalhe_votacao_secao_2026_BR.csv` | `6294ff8ecee0471d5a480c23b5a32dab231ec185c2e2d9d24d0d6a3020b7d2b8` |

CRC dos arquivos extraídos foi conferido. Votação 2022 BR e detalhe AC 2022 já
estavam no catálogo; o detalhe BR só contém presidente, sem sobreposição de cargo
com o detalhe AC anterior. Três ingestões adicionais completaram 3.800.511,
944.150 e 499.248 registros, com comparação integral CSV/Parquet por bloco.

O diagnóstico exaustivo encontrou 135 registros explicitamente marcados como
seção **não instalada**, com aptos positivos e contadores de participação zero.
São 47 por turno de 2022 (657 aptos cada) e 41 em 2026 (423 aptos).
[Evidência bruta](../design/evidence/participacao-discrepancias-source.json)
guarda as linhas e hashes; nenhum arquivo original foi alterado.

`analytics.py` trata exclusivamente o placeholder de abstenção zero como `NULL`
quando seção não instalada, aptos positivos e comparecimento zero. Preserva
aptos, comparecimento, válidos, brancos e nulos observados e fontes sem esse flag.
Não calcula abstenção como aptos menos presentes. As somas estritas e os gates
de integridade continuam em vigor. Isso pode tornar a abstenção nacional
indisponível mesmo quando a soma bruta dos placeholders existe.

`INITIAL_BUILD_GATE=NOT_RUN`: correção preventiva baseada na evidência integral,
antes do build E6. Não se inventa uma execução CLI com falha. Publicação e
conferência finais são registradas abaixo quando efetivamente concluídas.

## Verificação operacional

Build canônico E6: `PASS`, run `751083ec-1ebf-4606-997e-038dd26718ac`,
6.403.273 resultados de seção e 1.451.898 registros de participação no staging
(inclui demonstrações privadas, excluídas da publicação). `validate` independente:
`PASS`, sem erros. A primeira publicação falhou na comparação integral `EXCEPT
ALL`, por limite operacional de spill DuckDB de 2,6 GiB. A exportação havia
passado; o publicador removeu o diretório parcial. `INITIAL_PUBLICATION_GATE=FAIL`.
`FINAL_PUBLICATION_RERUN_1=FAIL`: 4 GB de memória/uma thread provocaram pressão
de paginação do Windows e o espaço de spill caiu a 230 MiB. Essa tentativa
também não qualificou o snapshot e seu diretório parcial foi removido.

A correção operacional em `publication.py` mantém o `EXCEPT ALL` bilateral em
partições disjuntas por ano/turno/cargo/UF presentes no schema. Enumera a união
das chaves de origem e destino, usa `IS NOT DISTINCT FROM` para incluir chaves
NULL e soma todas as divergências. Não há amostragem ou eliminação de duplicatas.
Revisão do helper e conferência manual da equivalência monolítica/particionada:
duplicatas e NULL iguais retornaram 0/0; duplicata faltante, NULL extra e chaves
exclusivas retornaram 4/4. A configuração voltou a 512 MB/uma thread.

Foram removidos exclusivamente sete Parquets intermediários gerados nesta tarefa
em `data/marts/751083ec-1ebf-4606-997e-038dd26718ac`, liberando 425.824.561 bytes.
Eram cópias reconstruíveis dos marts persistidos no DuckDB; publicação e validate
leem as tabelas persistidas, não esses exports. `current.json`, catálogo, recibos,
fontes, ZIPs, banco e snapshot E5 foram preservados. O caminho do run no recibo
de build não deve ser interpretado como sete exports privados ainda presentes.
`FINAL_PUBLICATION_RERUN_2=FAIL`: o `COPY` da view de resultados de seção
excedeu 772,8 MiB de spill antes de chegar à comparação particionada, devido
ao join com participação. O arquivo de exportação ainda tinha zero bytes;
o diretório parcial foi removido. A exportação está sendo particionada também,
sem alterar views, schema ou dados, seguida de consolidação e comparação
integral do Parquet final. Nova qualificação permanece pendente.

Em execução: publicação do snapshot `e6-2022-2026-v1` e smoke final de 2026.
O snapshot E5 anterior permanece intacto. Os handoffs E3/E4/E5 não foram
reescritos para alegar cobertura que não tinham.

Concluído: `npm ci`, `npm run typecheck` e `npm run build`. O build final
TypeScript + Vite conferiu 677 módulos sem erro, depois das correções de dados,
versão de cache e disponibilidade contextual. Build local servido
por `npm run preview -- --host 127.0.0.1 --port 4173`, com fallback de rota e
proxy da API verificados. `npm run dev` também funciona na porta 5173.

Manuais já executados: navegação desktop/mobile, menu e preservação de filtros,
UF → município → zona → seção, Lula 2022/AC/1139/7/71 = 271 votos; detalhe,
consulta JSON, CSV com filtros/versão/NULL; modal de doação explicitamente não
configurada; guia expansível; metodologia/download de nota; erro de seção 404
e nova tentativa. Capturas React em `docs/design/evidence/`.

A API recebeu conferências diretas HTTP/Parquet de E5, validação de rate limit
429 com Retry-After, timeout real 504 e rejeição de manifesto adulterado. Esses
checks não constituem prova de 2026; a reconciliação da nova versão precisa
constar separadamente. Nenhuma infraestrutura de testes, mocks ou CI foi criada.

## Arquivos principais

- `frontend/`: aplicação, dependências fixadas, assets, estilos e configuração.
- `src/eleitoral/api/`: serviço público e verificação de snapshot.
- `src/eleitoral/analytics.py`, `src/eleitoral/publication.py`: disponibilidade
  causal e limitação publicada, preservando contratos e fontes.
- `pyproject.toml`, `uv.lock`: dependências API e empacotamento restrito.
- `.gitignore`, `.env.example`, `README.md`, `docs/architecture.md`: operação.
- `docs/design/`, `docs/deploy/`, `frontend/README.md`, este handoff: evidências
  e documentação da entrega. Dados brutos, bancos, snapshots, node_modules e
  dist são ignorados pelo Git. Nenhum commit ou deploy externo foi realizado.
